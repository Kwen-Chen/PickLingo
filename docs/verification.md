# 选中、复制与结果面板回归验证

## 自动化验证

```sh
./scripts/test.sh
```

测试使用独立的临时配置目录和受控的响应，不访问真实 AI 服务，也不改写用户的剪贴板。
覆盖延迟 AX 返回时复制/切换应用、重新选中相同文本、保留代码缩进、多屏坐标、编辑快捷键冲突、黑名单持久化、旧请求返回、停止流式请求、本地命令大量输出、占位符转义、取消和超时。
还覆盖监听失效与权限变更后的恢复、非激活工具栏点击路由、设置控件误触发防护、工具栏样式和位置持久化，以及选区边界定位和屏幕边缘避让。

若主机的 `xcodebuild` 暂不可用，但已安装独立 Command Line Tools 和 Xcode 的 XCTest：

```sh
PICKLINGO_USE_CLT=1 ./scripts/test.sh
```

此方式编译并用 XCTest 执行测试，不会接受许可协议或修改 `xcode-select`。标准应用构建仍需可用的 Xcode：

```sh
xcodebuild -project PickLingo.xcodeproj -scheme PickLingo \
  -configuration Debug -derivedDataPath build/DerivedData \
  CODE_SIGNING_ALLOWED=NO build
```

## 跨应用人工检查

这些场景需要启动新构建的 PickLingo 并授予辅助功能权限。自动化测试不能替代目标应用中的真实交互检查。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 标准 API | 配置兼容服务，分别测试 HTTP/HTTPS、流式与非流式 | 连接成功，不发送 `reasoning` 私有对象，SSE 按标准 delta 读取 |
| 菜单栏入口 | 启动应用；再次从 Finder／Spotlight 打开；切换浅/深色外观 | 菜单栏按钮可见且图标清晰；再次打开显示设置窗口 |
| 设置窗口 | 打开、关闭、再次打开设置；选中说明文字并按一次 ⌘C | 设置打开时显示 Dock 图标，关闭后回到后台；文字可选择、复制和触发工具栏 |
| 设置控件 | 留下文字选区后切换单选框、开关或滑块 | 控件不复用旧选区触发工具栏；API 密钥字段不参与取词 |
| 工具栏外观 | 选择四种样式；调整插件间距、上下位置、水平偏移和垂直间距 | 预览立即更新，已显示工具栏同步调整；重启后保留设置 |
| 工具栏按钮 | 让源应用保持前台，点击“翻译”“提问”；在结果窗口内滚动或右键 | 按钮完整收到按下和松开事件，显示结果或输入框；内部操作不被当成外部点击关闭窗口 |
| 监听恢复 | 授予/撤销/重新授予辅助功能权限，或唤醒设备；在受控测试中停用事件监听 | 关闭状态不会被自动启用；开启状态会恢复监听，不重复注册 |
| Ghostty 自动复制 | 启用终端/终端内程序的选中自动复制，选择 A 后只按一次 ⌘V；再快速选 B 并粘贴 | 分别得到 A、B；等待一秒后仍是最后一次复制内容 |
| VS Code | 拖选、双击选词后，立即 ⌘C / ⌘V；也用右键复制/粘贴 | 第一次即使用正确内容；无需再复制一次 |
| 已有剪贴板 | 先复制图片、文件或富文本；在其他窗口只选中文本，等待一秒后粘贴 | 剪贴板内容和类型不变 |
| 不支持 AX 的应用 | 正常复制，再打开菜单栏“处理已复制文本” | 显示插件条；选中本身不发送复制按键 |
| 连续操作 | 选中后立即输入、滚动、右键、切应用或关闭总开关 | 旧选区不会在之后突然弹出插件条 |
| 重选 | 关闭插件条后，在原位置重新选择同一个词 | 能再次显示插件条 |
| 多屏 | 分别在主屏、左侧/上方/下方副屏选择文本 | 按正确屏幕命中取词，插件条落在该屏幕可见范围 |
| 黑名单 | 将 Ghostty 加入黑名单，退出并重启 PickLingo；再移除 | 重启后仍禁用，移除后自动取词恢复 |
| 结果部分复制 | 在结果中选取一段文字后按 ⌘C | 只复制选中部分；⇧⌘C 或“复制”按钮复制完整结果 |
| 流式结果 | 输出中阅读、选中文字；点击“停止”或“重新生成” | 不会自动跳到追问框；旧请求不会覆盖新结果 |
| 插入/替换 | 在源编辑器保持选区，执行插入/替换 | 激活源应用后粘贴；结果保留在剪贴板中 |
| 插入时状态变化 | 源应用已退出，或等待激活时剪贴板被新复制更新 | 不向错误应用发送粘贴，显示手动复制提示 |
| 本地动作 | 执行大输出命令，再尝试停止长时间命令 | 窗口可响应，大输出不因管道填满而卡死 |

## 已知行为边界

- 自动取词仅使用辅助功能接口，不再模拟 ⌘C。某些终端界面、画布和未开放 AX 的控件需要使用“处理已复制文本”。
- 启动、切换应用及开始选中时，会按目标应用支持的能力启用辅助功能树（包括 Chromium/Electron 的 `AXManualAccessibility`、`AXEnhancedUserInterface`），不依赖逐个添加应用白名单。首次取词遇到树尚未就绪时只重试一次；复制、输入或切换应用会取消重试。
- 处理已复制文本是用户主动调用，独立于自动取词开关和应用黑名单；只有点击插件后才会执行处理。
- 插入/替换将结果保留在剪贴板，不再定时恢复旧内容；第三方应用并没有统一的“粘贴读取完成”通知。
- 插入/替换仍依赖源编辑器保留原选区，不应在结果生成期间移动源编辑器的光标后再执行替换。
- 本地命令限时 60 秒，每个输出流最多显示前 1 MiB；外部命令自行启动的独立应用按其自身生命周期运行。

## 菜单栏图标排查

`LSUIElement=true` 使 PickLingo 默认在后台运行；打开设置时临时显示 Dock 图标，关闭设置后恢复后台运行。菜单栏图标由运行中的应用创建。先在活动监视器确认 PickLingo 正在运行；再次从 Finder/Spotlight 打开可显示设置窗口并尝试恢复图标可见性。若图标仍被隐藏，检查全屏/菜单栏自动隐藏、刘海屏空间及第三方菜单栏管理器。系统拥挤折叠不由 `NSStatusItem.isVisible` 完全控制。

## 协议参考

请求字段依据 [OpenAI Chat Completions 官方文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。使用 `max_completion_tokens`；仅在启用 Think Mode 时发送 `reasoning_effort: medium`。具体模型是否支持推理参数由服务决定，错误会原样显示，不会静默降级或切换模型。
